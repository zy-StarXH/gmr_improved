# Temporal-GMR（I0）实现与冻结开发集报告

## 1. 结论边界

Temporal-GMR v2 已在不修改 `/root/gpufree-data/GMR` 的条件下实现，并在冻结 Step 10 开发队列的 15 条 LAFAN1→Unitree G1 动作、90,540 帧上完成配对评估。v2 满足预注册开发门控：突跳、速度超限和近限位指标改善，无新增 hard-fail，总体 fidelity pass rate 下降未超过 2 个百分点。

该结论只适用于已经查看过的开发队列。第 4 节冻结的 15 条正式测试动作尚未运行，因而不能把本报告解释为独立测试集结论，也不能推断对模仿学习成功率的因果效果。未校准 `quality_score` 未参与参数选择、门控或结论。

## 2. 方法与实现

### 2.1 整帧关节速度信赖域

对输出帧 (t)，以实际上一输出姿态 (q_{t-1}) 为参考。内部第 (k) 次 IK 前已累计使用的关节位移为

\[
d^{(k)} = q^{(k)} \ominus q_{t-1}.
\]

每个标量关节的整帧预算为 (b=v_{max}/f_{out})。对本次 QP 位移 (\Delta q) 施加

\[
-b-d^{(k)} \le \Delta q \le b-d^{(k)}.
\]

因此 GMR 的两个任务阶段和每阶段最多 11 次内部求解共享同一预算，而不是每次按照 MuJoCo 的 0.002 s timestep 重新获得预算。约束范围与冻结速度指标一致，只覆盖 29 个受限 hinge 关节，不覆盖浮动根；第一输出帧没有虚构的上一观测，不施加时序信赖域。

v1 直接使用冻结评价阈值 (3\pi=9.42477796076938\) rad/s。它的 1,050 个“超限帧”最大 excess 仅为 (1.78\times10^{-15}) 至 (7.11\times10^{-15}) rad/s，属于落在严格 `>` 判定边界上的浮点误差。该负结果完整保留。v2 在查看 v2 结果前把求解上界固定为评价阈值的 0.999，即 9.41535318280861 rad/s；其他参数不变。

### 2.2 跨帧正则

在原两阶段目标中加入 Mink `PostureTask`，目标为上一实际输出帧，cost 为 1.0。Mink 的该任务自动忽略 floating-base 自由度。它是软目标，不会用后处理裁剪替代 IK；第一帧 cost 临时设为 0。

### 2.3 软限位余量

对每个关节定义软区间

\[
[q_{min}+0.03(q_{max}-q_{min}),\ q_{max}-0.03(q_{max}-q_{min})].
\]

只有当前关节进入软区间外侧时，分段二次任务才激活并把目标指向最近软边界，cost 为 10.0。原始 Mink `ConfigurationLimit` 仍作为硬约束，软目标不替代硬限位，也不对输出做限位裁剪。

### 2.4 接口问题与修正

代码核对确认，当前 Mink 1.2 的 `solve_ik` 第六个位置参数是 `safety_break`，`limits` 必须作为后续参数传入。若照搬当前上游 GMR 的六位置参数调用，新 limit 列表不会进入 QP。A1 使用显式 `damping=...`、`limits=...` 关键字；A0 仍保持原实现，未修改上游仓库。该问题不改变冻结 A0，因为其生成配置原本就是 `use_velocity_limit=false`，且 Mink 默认仍加载 `ConfigurationLimit`。

## 3. 实验协议

- A0：复用 Step 10 冻结 GMR 输出；另以 3 帧短前缀测试确认禁用 Temporal 扩展时与原 GMR 逐元素一致。
- A1：同一 15 条 source BVH、同一帧数、30 Hz、solver=`daqp`、damping=0.5。
- 完整评估：原质量项目的冻结 `unitree_g1_v1.yaml`，15/15 fidelity 状态为 `enabled_verified`。
- 分母：突跳和速度率使用 90,525 个有效相邻帧区间；其他帧率使用 90,540 帧。
- 门控：突跳率、速度超限率、近 2% 限位率严格下降；无新增 hard-fail；总体 fidelity pass rate 下降不超过 0.02。
- 不使用未校准综合分数；副作用指标不折算成单一分数。

## 5. 分层与失败案例

五类动作的突跳率和速度超限率均降为 0，近 2% 限位率在五类中均下降。standing/walking 的 fidelity 略升 0.00055；complex dynamic 和 floor motion 分别下降 0.00630、0.00793；dance 和 running/jumping 分别下降 0.02493、0.02568，超过总体门限的类别级幅度。

逐动作存在两个重要反例：`dance2_subject2` 的 fidelity pass rate 下降 0.03766，`sprint1_subject4` 下降 0.06053；`fallAndGetUp2_subject2` 的近 2% 限位率反而增加 0.000203。它们不改变预注册“总体”开发门控，但说明固定全关节信赖域在高速动作上会产生明显 tracking trade-off，软限位也不是逐动作单调改善。

与 I0 目标无直接约束关系的指标没有系统改善：总体碰撞、穿地、严重穿地和脚滑略有恶化，12/15 hard-fail 仍然存在。因此 I0 不能替代后续 Collision-GMR 或 Contact-GMR，也不能声称解决动力学可执行性。

逐类别精确表见 `data/TEMPORAL_GMR_CATEGORY_COMPARISON_V2.csv`，逐动作表见 `outputs/temporal_gmr_comparison_v2/paired_motion_metrics.csv`。

## 6. 验证与可复现性

- 单元/集成测试：15 passed；包括累计预算合成测试、软限位激活方向、A0 三帧逐元素一致性和旧 Step-3 源码哈希锁。
- v1、v2 独立审计均为 `ok=true`、0 mismatch；v2 覆盖 15 条、90,540 帧、18 个质量输出和 3 个比较输出。
- v2 逐帧诊断的最大信赖域占用比为 `1.000000000000001`，在审计容差内；输出评估得到 0 速度超限。
- GMR 参考仓库保持只读；其原有 dirty 文件未被处理。

主要复现入口：

```bash
cd /root/gpufree-data/gmr_improved
PYTHONPATH=src conda run -n gmr python -m gmr_improved.temporal_cli \
  --config configs/temporal_gmr_v2.yaml \
  --output-dir outputs/<new_empty_generation_dir>
```

生成后用质量项目的 `gmr_quality evaluate` 对生成目录和 catalog 做完整评估，再用 `gmr_improved.temporal_compare_cli` 与冻结 A0 配对比较。正式命令必须写入新空目录，不能覆盖本报告引用的 v1/v2。
